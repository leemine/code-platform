# 云目录连接寿命、断线分类与分段耗时

基线 main 286fde2。实际本地 UI 经同源 HTTP、账号 HTTPS、独立目录 WebSocket、云端原 Gateway/Router/工作区执行链读取目录。原来已有连接池，并非每次都建立新连接。新测同一次登录首个 list 51.373 秒，随后五次为 2.042、2.082、2.031、1.997、2.025 秒。首个请求前身份 7.611 秒、目录阶段约 40.9 秒、后身份 2.854 秒；云端 status 上游处理约 15～17 毫秒，公网 TCP 统计有重传，不能把全部延迟归因于权限查询。

已确认代码层问题：目录池以绝对 monotonic 五分钟桶作为 key，刚建好的连接跨桶也会被丢弃；60秒空闲回收容易命中用户浏览/输入间隔。WebSocket 处于 CLOSING 时旧 closed 属性仍可能为 false，操作随后陷入关闭等待；默认 close_timeout=5 的客户端多阶段关闭会延长失败返回。云端撤权的1008关闭被本地统一映射503，混淆权限拒绝与网络错误。

改为账号令牌摘要、端点和信任文件指纹隔离；目录连接空闲180秒、从实际建连时间起300秒后在下一请求重建，维持4项容量。工作区心跳等待60秒与原 WebChannel 配置对齐，仍保持150秒操作预算；同步专用连接心跳20秒不变。只复用 OPEN 连接；关闭阶段每段1秒，真实无响应关闭测试整体4秒内退出。账号 HTTP 空闲保留60秒，仍在使用前检查EOF/关闭通知。1008按未授权返回，其他断线仍失败且不重放任何写入。

前后身份检查、云端逐请求与交付权限检查、TLS/主机名校验、信任文件变化、账号隔离和原实例生命周期保留。每次实际操作重新访问权威，不缓存权限。新日志和 Server-Timing 区分准入、前身份、工作区操作、后身份；目录日志区分排队、建连、RPC，断线仅记关闭码和异常类型，不记账号令牌、目录内容或对端原因文本。

codeswarm 24f29148 不包含本工程 cloud_workspace_client，不能声称已从上游搬入同一目录池；继续复用既有客户端和原协议，不引入第二套前端、调度或执行机制。

验证：51项相关同步/目录/执行桥/代理回归通过；另4项 transport（含故意不回应close的真实回环服务）通过。新增跨五分钟边界仍复用、实际寿命到期重连、复用期间撤权无内容、关闭后下次重建测试。首轮新增撤权测试发现503分类问题并修复，原失败日志保留。源码1595文件与非editable安装一致，Core锁定e089198、协议2a0457e，255项wheel资源与干净前端构建一致。实际非editable安装包52项影响面测试通过。真实API连续6次目录读取均200，首次4.950秒、后续1.941/2.046/2.102/1.971/1.963秒；第三次后空闲70秒，日志确认第四次无重建。右侧目录列表、选择打开、新建directory-reuse-20261116及打开通过；独立再次读取确认目录存在，旧history14条3.869秒，已开WS撤权1008及后续目录401、无数据交付通过。首次UI冷目录16.772秒（握手9.687秒），新建6.851秒中RPC0.622秒、后身份5.572秒，公网抖动仍存在；不能宣称所有首次请求都达到4.95秒，也不把首轮51秒到4.95秒全部归因于代码。右侧退出→统一登录→旧会话正文恢复成功，页面始终为本地29011；检视未发现阻断问题。正式CI/合入仍待完成。

本地证据：artifacts/platform-directory-reuse-20261116/evidence（管理仓目录，不加入产品）。网络条件影响实际耗时；延长复用只能减少重连，不能消除公网丢包。后续修改连接/权限/部署来源时须重验。

补充负向对照：原主线在不回应close帧时实际等待9.010秒；asyncio.wait_for(4)的取消本身可能等待库清理，不能单独作为4秒完成证据。测试增加真实monotonic耗时断言后，原主线明确失败、候选4项transport全部通过，候选清理小于4秒。产品实现未再变化。独立公网候选对照另出现握手reset/身份超时，保留失败，不将成功窗口宣称为稳定网络基线。
