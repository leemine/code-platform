# 临时日志部署适配器：配置与退出契约

本适配器填补当前固定元戎Docker执行器共享日志挂载的缺口。它是可替换的宿主部署组件，不是Code-platform业务服务、长期日志平台或通用Docker授权网关。平台只要求“本环境日志可用，其他账号和平台日志不可见”；Gateway、Router、Runtime、账号/环境数据库不读取代理地址、命名规则或日志目录算法。

## 接入与职责

- 元戎通过已有Unix Docker端点发出原请求。适配器只改写创建请求里已配置共享日志根的bind源，保持容器目标路径、命令、环境、资源和原生命周期；不分配实例、不认证账号。日志功能本身不存业务状态；显式启用物理确认时另保留最小部署派发回执，详见后文。
- 日志按可信`/data`挂载源工作区分目录；`/data`是现有执行镜像挂载契约，不是账号ID接口。目录名规则仅来自可信部署参数，不得从HTTP/WS请求、账号表单或Agent传入。
- 原实例链仍负责创建、连接、回执、恢复及回收。日志采集/配额/保留由运维负责。`resource_pool_id`不是此适配器前置，平台不增加proxy/native业务开关或自动探测插件。
- 宿主运维管理适配器进程、权限及固定版本。socket必须放在0700私有目录中且仅供可信控制进程使用，不挂进Agent，不公开TCP；该代理能访问真实Docker控制接口，非创建请求仍透传。

## 显式配置

| 参数 | 契约 |
|---|---|
| `--listen` | 必填，私有Unix socket绝对文件路径，不带`unix://`；父目录规范、0700、当前操作员所有。默认拒绝已有socket；显式恢复参数的受控条件见运行保障章节。 |
| `--upstream` | Docker Unix socket文件路径，不带`unix://`；原默认`/var/run/docker.sock`保留，部署应显式填写核验后的目标。 |
| `--workspace-root` | 必填，规范绝对路径；预建0700根且属主为`--uid`；只接受其直接子目录。 |
| `--workspace-name-pattern` | **必填，无默认值**；Python正则，以ASCII模式编译，对单个目录名执行`fullmatch`。平台装配填写`env_[a-f0-9]{32}`；其他部署可显式使用不同规则。长度最多256字符，空/非法正则及匹配空名、`.`、`..`或列明典型分隔路径的规则拒绝启动。仅使用简单、有界规则，不接受不可信方提交的复杂正则。 |
| `--private-log-root` | 必填，操作员所有的规范绝对路径、0700，与工作区/共享日志根不重叠；不得挂入Agent。 |
| `--shared-log-dir` | 必填、可重复，实际执行器自动挂载的宿主共享日志根。必须从真实启动配置/挂载核对，不能由CLI日志前缀猜测。当前只支持原目标路径等于源路径的共享bind。 |
| `--image` | 必填、可重复，明确允许的Docker Image请求值；生产装配固定镜像摘要，不使用可变标签。 |
| `--user` / `--uid` | 必填，实际非root镜像登录名与宿主工作区UID；保持现有同UID/GID部署约束，不自动调整已有目录属主或权限。 |

命名正则只做名称准入，不能放宽直接父根、规范路径、无链接、0700及属主检查；目录名最多255字符，拒绝NUL和反斜杠。日志叶目录仍按工作区绝对路径SHA256生成，与命名规则文本无关；同工作区改变兼容规则不会迁移日志。调整工作区根或私有日志根则属于单独迁移，不能只改参数假定原日志自动可见。审计里的历史`account`字段仅是工作区叶名，不是账号权威身份。

旧实验启动命令必须显式补命名规则，否则新版本在创建socket前拒绝启动。没有隐藏的env_/u_兼容回退；历史服务器脚本/证据对应旧版本，不能混用为本版启动配置。

下面是部署参数示例，不会自动建立目录或启动元戎；镜像摘要和实际路径须由运维填写：

```bash
python3 deploy/cloud-workspace/docker_log_boundary.py \
  --listen /run/code-platform-log/docker.sock \
  --upstream /var/run/docker.sock \
  --workspace-root /srv/code-platform/workspaces \
  --workspace-name-pattern 'env_[a-f0-9]{32}' \
  --private-log-root /srv/code-platform/private-logs \
  --shared-log-dir /var/log/yuanrong/current-runtime \
  --image 'sha256:REPLACE_WITH_VERIFIED_IMAGE_DIGEST' \
  --user agentos --uid 1000
```

元戎内嵌DockerExecutor启动环境设置`DOCKER_HOST=unix:///run/code-platform-log/docker.sock`，使用到的`values.runtime_launcher.docker_host`同址。仅改其中一处不足；当前固定执行器的`tcp://`值会退回默认socket，禁止这样装配。代理不可用时不允许自动改回真实Docker socket。启动前记录适配器内容摘要、部署参数及元戎/Docker版本；本适配器不自安装、不升级SDK、不注册全局服务。

## 替换验收与退出路径

替代方式可以是上游原生私有日志挂载或其他受支持部署机制。只由部署装配选择一种生效方式，不在平台数据库记录proxy/native类型，不建立第二资源池选择链。当前没有实现或验证上游原生替代机制，不能配置一个不存在的native模式。

1. **先验证替代机制**：在隔离候选使用同一组与实现无关的场景——原Router自动创建/复用；实际完整挂载中私有根和其他账号目录缺席；自身SDK日志可写；其他账号及平台合成日志不可读；重建/重连/轮转/回收后仍成立；故障不得退回共享根；旧环境保护成立。代理进程或某个字段存在不算验收通过。
2. **冻结新创建并保留旧绑定**：由运维安排切换窗口，核对在途创建回执；不改账号ID、环境ID、epoch、固定镜像或凭据来迁就日志实现。已有容器的挂载不会因改配置自动改变，不原地改挂载或销毁旧数据。
3. **仅切换部署接线**：新底座用已验收的替代日志配置，再移除它的代理端点覆盖。已有实例继续沿原生命周期处理；如重建，必须单独授权并保护原持久工作区。需要正常上游版本升级时仍走既有来源锁定流程，不打SDK补丁。
4. **回退到上一个已验证隔离配置**：替代验收失败则停发新创建，保留回执并对账；不能回退到未隔离的原共享日志挂载。回退不覆盖账号库或环境库，不自动切镜像。
5. **最后退役适配器**：确认无进程和在途操作再依赖代理后，停掉其专属服务，核对PID/监听归属后移除socket与配置。历史私有日志保留到采集和保留策略完成；不随代理退出删除。最后可删除部署脚本及专项测试，平台业务接口和持久数据结构无需迁移。

## 临时适配器的最小运行保障（2026-11-10增量）

运行保障仅在部署层实现，不改变实例权威或增加请求回放。参数如下：

| 参数 | 默认与范围 | 行为 |
|---|---|---|
| `--max-connections` | 32，1～256 | 接受连接后、创建处理线程前占用名额；满额返回503并关闭；处理结束归还。不提供公平排队或业务优先级。 |
| `--request-timeout` | 30秒 | 客户端请求头/体读取及向客户端写入的socket超时。 |
| `--connect-timeout` | 5秒 | 连接指定Docker Unix上游的超时。 |
| `--upstream-timeout` | 60秒 | 上游请求写入和普通响应读取的socket超时；响应尚未发送时返回502，否则关闭不完整响应，不拼接第二个HTTP错误。 |
| `--stream-idle-timeout` | 300秒 | Upgrade连接双向无数据的最长等待；超过则关闭。仍受各方向写入超时约束。 |
| `--recover-stale-socket` | 默认关闭 | 显式开启后，在专属私有目录、操作员属主/权限检查和进程锁成立时，只恢复确认连接被拒绝且inode未变的残留socket。 |

超时必须为有限正数且不超过3600秒；这些是socket空闲/单次IO边界，不是整个请求的绝对执行期限。持续慢速流量仍可能占用有限名额；组件只供可信控制进程使用，不能替代授权网关。部署需按实际Docker操作及客户端期限调参，长时间无输出的流可能被关闭，不能把固定版本验收扩展到全部流式接口。

启动持有`<listen>.lock`的非阻塞flock，锁文件必须是当前操作员所有、0600、普通且单链接的文件，拒绝符号链接；锁文件保留，不按PID删除。仅接受root/操作员所有且无组/其他权限的旧socket；普通文件、链接、活监听、探测超时或其他错误均拒绝恢复。私有父目录只能由同一部署操作员管理，其他程序不得占用该端点。SIGTERM/SIGINT退出清理只移除本进程创建且inode一致的socket；SIGKILL后的残留由下一次带恢复参数的启动处理。退出会断开在途请求，结果未知时交给原Router/元戎查询与对账，适配器不重试创建/删除，也不改回真实Docker或共享日志。

托管复用[systemd单元模板](systemd/code-platform-log-boundary@.service)和[环境配置示例](systemd/instance.env.example)。模板使用Restart=on-failure、2秒重启间隔、60秒内最多5次启动，并限定文件描述符、任务数和内存；达到启动限制时保持失败，运维核对故障后才恢复，不自动reset-failed循环。采用原生配置语义，参见[systemd服务文档](https://www.freedesktop.org/software/systemd/man/255/systemd.service.html)。无新增监督进程、实例数据库、自动升级或安装脚本。

模板部署需显式安装固定版本脚本至示例ExecStart路径，预建并核验工作区与私有日志根，把真实参数放入操作员所有的0600 EnvironmentFile。模板只排序在已有Docker服务之后，不启动、停止或重启Docker；每个实例名使用独立RuntimeDirectory和私有socket。元戎环境及runtime_launcher参数必须指向该实例的同一端点。模板不是现网启用授权；新单元先在专属底座验证，再进入另行授权的部署流程。

故障验收必须同时观察平台持久回执、原元戎清单及实际Docker容器/挂载：代理停机、指定Docker端点不可用、创建已提交但响应丢失、删除响应超时均不得触发适配器重放或回退。仅代理自动恢复不代表原实例操作自动恢复成功；结果未知时保留回执并沿原链对账，确认删除后才能推进epoch。真实服务器结果及未通过项另见PLATFORM_CLOUD_LOG_ADAPTER_RELIABILITY_20261110，不以本契约声明代替验收。

**上一轮验收限制（旧候选历史）：** 创建已提交/响应丢失故障中，systemd恢复成功，但出现“元戎API404、Docker仍有created容器”的分歧，并在后续原链重试中触发重复物理容器断言。该旧候选存在物理唯一性阻断；后续当前候选已补下述物理对账并完成隔离复验，历史记录不转写为成功。实例层须建立充分物理对账依据，未知结果不得仅凭代理恢复放行。人工清理任务残留不是产品自动修复，不宣称全部故障安全通过。

## 原实例链的物理完成契约（2026-11-10增量）

上节描述的是旧候选真实失败。新增物理完成保护只对显式启用的新隔离底座生效，验收记录见 `PLATFORM_CLOUD_PHYSICAL_RECONCILIATION_20261110`；不能据此认定旧环境已修复。

原 Router 仍唯一负责创建、连接与删除。其两个既有删除入口在元戎 GET404 后、注销及 `DELETED` 前调用可选异步 `confirm_deleted`。云环境策略从持久绑定取工作区、固定镜像、执行用户、该 epoch 的凭据目录和实例 ID，验证状态/epoch 后调用受限 Unix 接口。失败保持 `DELETING`，后续 ensure 沿原删除入口重试，不推进 epoch。宿主不理解 Docker、目录命名规则或派发回执。

临时部署适配器额外启用六个参数，必须一起提供；缺少任一参数启动失败：

| 参数 | 契约 |
|---|---|
| `--physical-journal-root` | 新建、操作员所有0700、与工作区及凭据根分离的持久派发回执目录；不挂载给 Gateway/Agent，不随进程重启丢弃。 |
| `--identity-root` | 与平台 `state_root/instance-auth` 一致的规范绝对路径，执行UID所有0700。 |
| `--identity-target` | 当前为 `/run/jiuwenswarm`；必须与实际只读凭据挂载一致。 |
| `--reconcile-listen` | 独立Unix确认socket；父目录操作员所有、组为Gateway GID、0710；socket操作员所有、同组0660。只将父目录只读挂入Gateway，不给Agent挂载。 |
| `--reconcile-frontend` | 本底座原元戎Frontend地址，补偿前再次确认实例GET404；错误/超时拒绝确认。 |
| `--reconcile-gid` | Gateway非root组；不能授予完整Docker代理socket权限。 |

Gateway的 `resource_reconciler_socket` 指向容器内该确认socket。该配置使新绑定固定 `physical_verification=true`，绑定比较禁止静默启用、关闭或切换回不验证模式；地址属于部署配置，不写入业务绑定。原未启用绑定保持旧兼容行为，不自动迁移；因此不能将升级应用镜像等同于完成物理保护。

受限接口只支持 `POST /v1/confirm-deleted`，字段恰为 `workspace/identity/image/user/instance_id`，请求体最多8192字节；成功200且 `absent=true`，未证明完成返回503。不支持任意Docker转发、强制删除、卷删除、列出其他环境。Gateway使用15秒超时、无重试的既有HTTP客户端；创建/回收SDK不改。

适配器从已审核的创建请求提取工作区及只读凭据挂载，以工作区hash生成唯一Docker名字，以工作区和凭据目录hash标记epoch归属。同一工作区持有非阻塞文件锁；转发前持久化最小 `NOT_SENT→SENT` 回执，收到有效201后先落 `CREATED` 再回复。既有同代回执、未结束旧代或占用物理名字时拒绝再次派发。回执只含路径、镜像、用户和物理标识，不存口令、令牌、环境变量或命令，不取代平台环境数据库。

原删除流程请求确认时，部署侧校验上述归属与原API404：只对镜像、用户、scope标签、工作区/凭据挂载完全匹配，且状态created、从未启动的容器做一次非force、不删除卷的补偿删除，再确认物理404并持久化 `DELETED`。这是原删除的同步补偿，没有后台扫描、第二创建器或独立回收调度。运行过的容器、归属不同、检查失败均保留待处理状态，不强删。旧代 `DELETED` 回执保留以拒绝迟到创建。

**保守边界与成本：** 若仅有SENT而从未观察到有效容器/201，即使当前物理404也不自动认定未执行，避免延迟提交后产生孤儿；需运维核实在途操作并沿原链恢复。回执需持久化、备份且不得任意删除；同工作区的历代回执占用磁盘并参与校验，暂未自动压缩。新增一次Unix确认调用、元戎/物理查询及fsync；依赖确认服务可用，故障时宁可暂缓重建。固定名字只保护本专属底座经适配器的请求，绕过socket、跨节点或人工删改回执不在保护范围。

**可替换退出：** 日志隔离与物理确认是两个独立契约。未来原生底座可替代任一项；切换前冻结创建、排清在途SENT与DELETING，验证同代防重、迟到拒绝、真实物理完成和持久数据保留。替代服务继续履行同一确认接口/绑定能力；不能通过关闭配置绕过保护。只有所有旧代派发者停用、回执不再被引用且替代机制验收后，才退役该部署模块。SDK原生升级仍走锁定来源流程，不热补丁。

候选已收敛；操作接线、状态恢复、备份及回退边界见[候选交付说明](CANDIDATE_HANDOFF.md)。本轮不安装服务或变更现网。
